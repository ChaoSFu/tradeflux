# TradeFlux · 短线晴雨表

> **把交易者从人性的奴隶,训练成规律的操作者。**

市场不奖励最聪明的人,奖励最能管住自己的人。TradeFlux 让**客观的市场**照进**主观的你**,用 AI 居中做不带情绪的教练,把「知」一次次拉齐「行」——并在你终于知行合一后,让自己变得不再必要。

> ⚠️ 本平台提供市场数据分析与个人行为复盘,**不构成任何投资建议或买卖指令**,不做自动交易,不保证任何收益。交易决策请自行承担风险。

## 为什么能盈利 · 交易的理论

市场扣除成本后是**负和游戏**,平均的参与者必然亏钱。散户拼不过机构的信息与分析——唯一可长期依赖、且可训练的优势是**纪律:在别人做不到时,做到你本就知道该做的事**。

```
盈利 = 胜率 × 平均盈利 − 败率 × 平均亏损 − 成本
```

四条结构性规则:

1. **顺势** — 不与趋势为敌。大势为守时,逆势买入即降低胜率。
2. **截断亏损 · 让利润奔跑** — 盈亏比是命门。快砍亏损、拿住盈利,才不被处置效应反噬。
3. **固定风险仓位** — 每笔只赌固定比例。越上头下得越重,是爆仓的唯一原因。
4. **低频 · 高确定性** — 只做高确定性机会。越频繁,成本与情绪犯错越多。

> **大概率盈利 = 顺应规律 × 执行纪律**——四条全是「行为」不是「预测」。你不需要预测未来,只需要不偏离你已经知道的对的事。

## 两个引擎

- **🔭 读市场 · 客观规律引擎** — 指数均线趋势、板块轮动退潮、涨跌停与一字板、情绪温度与建议仓位。回答:现在什么环境、主线在哪、该攻还是该守。
- **🪞 照自己 · 人性纠偏引擎** — 记录你的每一笔操作,发现逆势加仓、着急回本、不舍空仓等弱点,做出客观评价。回答:我又在重复哪个错、这次怎么管住自己。

## 项目现状

当前仓库是一个前后端分离的单体应用：

- **后端**：FastAPI、SQLAlchemy 2、Pydantic 2、APScheduler。
- **前端**：React 18、TypeScript、Vite、Tailwind CSS、TanStack Query、
  Zustand、Recharts。
- **数据库**：默认使用 PostgreSQL；本地体验也可通过 `DATABASE_URL`
  切换到 SQLite。
- **行情数据**：以东方财富为主，并使用 AkShare、新浪财经、腾讯财经作为
  列表、实时行情或 K 线补充/降级来源。
- **自动任务**：后端启动时注册盘后更新任务，交易日 15:30 后随机延迟执行；
  也支持从管理接口或脚本手动触发。

主要页面覆盖市场趋势、强势股池、板块趋势与情绪、涨跌停分析、弱转强信号、
自选监管、每日复盘和个人交易日志。AI 叙事目前主要是规则模板，并未接入
大模型推理服务。

## 本地开发

### 1. 启动后端

建议使用 Python 3.13。默认配置需要本机已安装 PostgreSQL，并存在
`tradeflux` 数据库。

```bash
cd backend
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --port 8000
```

如果只想快速体验，可将 `backend/.env` 中的数据库连接改为：

```dotenv
DATABASE_URL=sqlite:///./tradeflux.db
```

首次启动会自动建表。健康检查为 <http://localhost:8000/health>，交互式接口
文档为 <http://localhost:8000/docs>。

### 2. 启动前端

```bash
cd frontend
npm install
npm run dev
```

访问 <http://localhost:5173>。Vite 开发服务器会将 `/api` 请求代理到
`http://localhost:8000`。

### 3. 配置鉴权

管理功能使用 JWT 鉴权。生产或共享环境务必在 `backend/.env` 中覆盖默认值：

```dotenv
ADMIN_USERNAME=admin
ADMIN_PASSWORD=请替换为强密码
JWT_SECRET_KEY=请替换为随机密钥
```

随机密钥可用 `openssl rand -hex 32` 生成。不要提交真实密码、令牌或数据库
凭据。

### 4. 配置行情数据源（可选，但强烈建议）

K 线数据默认逐只股票去打腾讯／新浪的公开接口，一轮几百次请求——这是限流和
拉取失败的主要来源。配置 [同花顺官方金融数据 API](https://fuyao.aicubes.cn/)
之后，改为**一次下载全市场最近 10 个交易日的日 K**（约 1 MB，9 秒），请求数
从几百降到 1。

获取方式：用同花顺账号登录 <https://fuyao.aicubes.cn/admin>，在「API Key 管理」
页一键签发，然后写进 `backend/.env`：

```dotenv
FUYAO_API_KEY=签发得到的 key
```

注意 `.env` 由 pydantic-settings 加载，**不会注入 `os.environ`**；配置后重启
服务即可生效，日志里会打出 `📦 fuyao dump(1.0MB)：N/M 只直接命中`。

不配置也能正常跑，只是完全退回逐股接口：慢、且容易被限流。dump 只用于更新
库里已关注的股票，用完即删，不在磁盘留副本；新进候选池、需要 65 日窗口的
股票仍走逐股接口（dump 只有 10 个交易日）。

### 5. 初始化与更新数据

在 `backend` 目录、虚拟环境已激活的情况下运行：

```bash
python scripts/init_screening.py    # 初始化默认入池规则
python scripts/sync_boards.py       # 同步板块及成分关系
python scripts/daily_update.py      # 执行一次日常行情更新
```

这些任务依赖公网行情接口，耗时和可用性会受交易日、接口限流及网络状况影响。
详细的抓取降级、互斥锁与更新步骤见 [backend/BACKEND.md](./backend/BACKEND.md)。

- 外部行情接口并非稳定 SLA 服务，抓取逻辑包含降级但仍可能失败。
- 仓库暂未提供完整的自动化测试套件；修改核心计算逻辑时应结合
