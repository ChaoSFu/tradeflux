# 数据体检运维手册

> 2026-09-12 上线。页面：「数据体检」（顶栏听诊器图标，有可补的缺口时亮红点，数字 = 待处理项数）。
> 代码：`backend/app/services/data_audit_service.py`（检测）、`backend/scripts/data_audit.py`（命令行 / 补数）、
> `backend/app/routers/data_audit.py`（接口）、`backend/app/services/templates/sector_kline_console.js`（板块导出脚本模板）。

## 一、为什么要有

日更里很多步骤是「独立步骤，失败不影响主流程」：指数、市场宽度、涨停明细、监管快照、成交额前列、
板块日快照……失败了只写一行日志。没人天天翻日志，缺口就悄悄留下；等页面算出怪数再回头查，
往往已经过了能补的时间。数据体检把「查缺口」和「怎么补」都固定下来。

三条纪律：

1. **检测只读。** 写库一律走补数流程，登录后先试跑、再确认。
2. **「那天该有」要有参照。** 交易日由交易日历定；建表之前的日子不算缺；股票快照以 10 年存档里「那天有成交」为准，停牌不算缺。
3. **补不了的如实说补不了。** 只能当天拍的数据过了当天就没了，标「补不回来」、只记录、不亮红点。

## 二、什么时候跑

| 时机 | 说明 |
|---|---|
| 每次日更之后 | 盘后 15:30、盘前 09:27 那两次日更，跑完、板块同步之后接着体检（只读，子进程）。只能当天补的数据要趁当天发现，所以紧跟日更 |
| 周六 11:00 | 兜底：周中哪天日更整个没跑，体检也就没触发 |
| 页面「立即检测」 | 需要登录 |
| 命令行 | `python -m scripts.data_audit run`（加 `--save` 才写报告） |

报告：`backend/logs/data_audit/latest.json`，另留最近 30 份带时间戳的副本。检测和补数都跑在子进程里——
股票快照那项要读 10 年存档，常驻服务进程里跑会把内存峰值留在堆里（DATA_SOURCES.md 坑 18）。

## 三、检测什么

窗口 = 最近 65 个交易日（跟 K 线窗口一致）。截止日 = 今天是交易日且已过 15:30 就含今天，否则到前一个交易日。

| 检测项 | 怎么判缺 | 补法 |
|---|---|---|
| 交易日历 | 没有缓存，或最后一天和今天之间夹着工作日 | 下次日更自动刷新 |
| 10 年日K存档 | 比截止日落后 ≥2 个交易日 | 一键：重下存档（约 6 分钟，只写 `data/fuyao/`） |
| 个股日快照 | 按存档逐只核对（存档那天有成交、库里没行才算缺），外加整天一行都没有的日子 | 一键：用存档补洞（`full_dump heal --apply`，顺手重算市场效应） |
| 指数日线 | 5 个指数每个交易日一行 | 一键：从最早缺的那天起重拉（东财→腾讯→新浪） |
| 市场宽度 | 两融、成交额（最新一天不算，次日才公布）；涨跌统计 | 一键：日常同步 + 两融全历史回填；涨跌统计只能当天补 |
| 涨停 / 炸板明细 | 某交易日 0 行 | 一键：逐日向东财补（接口支持历史日期，太久远的可能不给） |
| 市场效应 | 每个交易日一行 | 一键：用库里快照重算（不向外部请求） |
| 龙头周期快照 | 每个交易日有行 | 一键：用库里 K 线重建（不覆盖已有行；注意幸存者偏差） |
| 板块指数日线 | 关注板块不足 70 根，或窗口里有洞 | 本机导出 → 服务器收件箱 → 页面导入（见第五节） |
| 日复盘 / 监管状态快照 / 成交额前列 / 板块日快照 | 每个交易日有行 | 今天缺：重跑今天的日更；更早缺：补不回来 |

状态：

- **要补**：计入红点。
- **提醒**：存档 / 日历落后、表是空的。
- **补不回来**：只记录，不亮红点。否则红点永远亮着，提醒就等于没有。
- **检测出错**：这一项本身查挂了（其余各项照常），计入红点。

## 四、补数的固定流程

所有写库操作都是**试跑 → 确认 → 自动复查**：

1. 页面上点「试跑」（需要登录）：只列出将补什么、补多少，不写库。
2. 数字没问题点「确认补上」：写库。已有行一律不覆盖（指数日线例外：它跟日更同一个函数，会用同一来源的值刷新）。
3. 补完后端自动重查这一项，写回报告，页面自动刷新。

命令行等价：

```bash
cd /opt/code/tradeflux/backend
.venv/bin/python -m scripts.data_audit fix <检测项>            # 试跑
.venv/bin/python -m scripts.data_audit fix <检测项> --apply    # 真的补 + 复查
```

- 补数拿日更那把锁（`/tmp/tradeflux_daily_update.lock`）：日更正在跑时退出码 3，什么都不动。
- 日更 20 分钟内就要开始时，页面上的「确认」会被拒绝——撞上了会让当天的定时日更因为拿不到锁而跳过。

## 五、板块指数：本机导出（2026-09-12 走通的做法）

生产服务器出口被 push2his 拒（2026-09-06 实测），板块指数历史只能在能连通的机器上取。
而开发机这边它也按频率限流：**约 2 秒一个、连取 20 个就被掐，至少封二十分钟，浏览器一样**。
这不是请求头或参数的问题，换头没用，只能慢。

1. 打开数据体检页，找到「板块指数日线」，复制导出脚本。脚本由服务器按当前缺口生成，已填好板块。
2. 打开东财行情页（https://quote.eastmoney.com/center/boardlist.html），先在页面空白处点一下
   （免得 Chrome 拦「下载多个文件」），然后 F12 → Console → 粘贴 → 回车。
   - **节奏**：起步 15 秒一个；被掐等 10～30 分钟再试并放慢；连续 30 个顺利再提速；连着被掐超过 3 小时才放弃。
   - **控制**：`__tfStatus()` 看进度；`__tfSave()` 先下载已取到的；`__tfStop = true` 停下（停前会下载）。
   - **注意**：电脑别睡、标签页别关。屏幕熄了或标签页在后台也能跑，只是会被浏览器限到约一分钟一个。
   - **续取**：停下后在同一页面（别刷新）再粘贴同一份脚本，只取剩下的。
3. 文件下载到浏览器的下载目录（这台机器的 Chrome 下载到桌面），再 scp 到服务器收件箱：

   ```bash
   scp ~/Desktop/sector_klines_*.jsonl admin@47.250.165.189:/opt/code/tradeflux/backend/data/inbox/
   ```

4. 回到页面的「收件箱」：先试跑导入（看新增、已存在跳过、解析失败各多少），再确认导入，自动复查。导完的文件挪进 `inbox/done/`。
5. 东财没有指数日线的板块，脚本会写一条空记录；导入时记下来，之后不再当缺口报。

备用 Python 路线（Python 没被挡时）：

```bash
python scripts/export_sector_klines.py --scope missing --out sectors.jsonl            # 默认 15 秒一个；连续失败 5 次停手
python scripts/export_sector_klines.py --scope missing --out sectors.jsonl --resume   # 过一阵接着导
```

## 六、加一个检测项

1. 在 `data_audit_service.CHECKS` 里加一项：id、标题、表、为什么会缺、判缺函数。按日写的表可以直接用 `_server_per_day` 或 `_same_day`。
2. 能在服务器上补的，同时在 `FIXABLE` 和 `scripts/data_audit.py` 的 `FIXERS` 里登记补法。有测试盯着两边一致。
3. 定口径之前，先在服务器上跑一次 `run` 看真实数据（先量再改）：某张表其实并不每天写，就别按「每天一行」判缺。
