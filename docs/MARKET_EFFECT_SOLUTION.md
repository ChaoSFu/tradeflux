# A 股赚钱效应与亏钱效应：产品与技术完整方案

> 文档状态：方案确认稿  
> 适用项目：TradeFlux · 短线晴雨表  
> 核心用户：只能做多、以短线或波段交易为主的 A 股个人投资者  
> 首期范围：沪深京全部 A 股，包含 ST、新股和退市整理股票  
> 周期原则：不预设持有周期；T+1 / T+3 / T+5 是观察锚点，实际周期跟随赚钱效应  
> 思想依据：[养家心法提炼](./YANGJIA_METHOD_NOTES.md)  
> 产品定义底稿：[市场效应产品逻辑](./MARKET_EFFECT_PRODUCT.md)

---

## 1. 方案结论

这个功能不应被做成又一个“市场情绪分”，而应被做成一套可追溯的
**多头交易环境识别系统**：

1. 先判断市场是否正在奖励风险承担；
2. 再判断正反馈发生在哪类策略、哪些板块和哪些核心股票；
3. 将正反馈的强度与持续性分开评价；
4. 识别追涨和低吸同时开始失效的负反馈形成过程；
5. 最终输出市场许可、板块许可和个股结构三个层次的决策证据。

产品的最小闭环是：

```text
前一交易日冻结参与群体
        ↓
下一交易日观察真实盈亏反馈
        ↓
判断正反馈/负反馈的强度、扩散和持续性
        ↓
生成市场生命周期与交易许可
        ↓
在后续 1/3/5 日验证判断是否有效
```

技术上的核心原则是：

> 外部行情只在数据同步任务中集中调用一次；计算服务只读本地事实表；
> 前端查询只读已经物化的结果，绝不因打开页面重复请求外部行情。

首期不需要为全市场每只股票重新请求一次 K 线。应复用现有数据源，并把：

- 当日全市场截面；
- 当前活跃池；
- 前一交易日冻结群体；
- 尚在观察期内的历史群体；
- 全市场关键板块核心股；
- 用户持仓和关注股；

合并为一个去重后的“每日跟踪股票集合”，对该集合统一增量补行情。

### 1.1 已确认的首期产品约束

| 决策项 | 已确认方案 |
|---|---|
| 股票范围 | 沪深京全部 A 股 |
| 特殊股票 | ST、新股、退市整理进入全市场广度；同时提供分层结果，避免特殊制度扭曲主样本 |
| 交易模式 | 不预设首板、连板、趋势或低吸；每天识别赚钱效应最强且最可持续的模式 |
| 决策周期 | 不预设固定持有周期；根据效应年龄、增强/衰减和 T+1/T+3/T+5 结果动态判断 |
| 市场许可 | 首期只给动作边界，不映射固定仓位 |
| 板块范围 | 扫描全市场行业和概念板块，采用分层计算控制接口开销 |
| 持仓联动 | 负反馈形成后检查现有持仓，输出分级警告和证据 |

## 2. 产品目标与边界

### 2.1 要解决的问题

用户每天需要获得五个答案：

1. 当前是适合做多、试错，还是应该停止新增风险？
2. 昨日追涨、接力、低吸和持有强势股的人，今天分别赚钱还是亏钱？
3. 赚钱是少数抱团，还是已经扩散到板块和全市场？
4. 当前赚钱效应已经持续多久、处于增强还是衰减，是否仍值得跟随？
5. 负反馈是局部预警、已经形成，还是正在向市场扩散？

### 2.2 不解决的问题

首期明确不做：

- 预测明日指数点位；
- 自动给出确定性的买卖指令；
- 用单个综合分替代全部交易判断；
- 高频盘中择时；
- 对全部 A 股保存完整分钟级行情；
- 因页面查询而实时抓取第三方行情；
- 把指数上涨直接等同于赚钱效应。

### 2.3 成功标准

产品是否有交易价值，不看页面是否丰富，而看以下历史验证：

- “允许做多”的日期，后续 1/3/5 日活跃群体收益显著优于基准；
- “负反馈形成”的信号，能够领先或同步于活跃群体的大幅回撤；
- 能识别“赚钱效应强但持续性弱”的高潮或脉冲行情；
- 能识别“指数强、短线接力弱”以及“指数弱、局部题材强”的错位；
- 状态不会因为单日噪声频繁翻转；
- 任一结论都能下钻到原始样本和事实；
- 历史回测严格使用当时已知信息，不发生未来数据泄漏。

## 3. 从《养家心法》转化出的产品原则

### 3.1 市场是参与者反馈的循环

赚钱效应的本质不是上涨家数，而是：

```text
昨日承担风险的人赚钱
→ 愿意继续参与
→ 吸引同类资金模仿
→ 核心股获得承接
→ 板块扩散
→ 更多参与者赚钱
```

亏钱效应的本质是：

```text
追涨者先亏钱
→ 接力意愿下降
→ 核心股失去承接
→ 低吸修复也失败
→ 支撑资金撤退
→ 亏损从高位扩散到中低位
```

因此，最重要的数据不是“今天选出的强势股今天涨了多少”，而是
**昨天已经承担风险的人今天获得了什么结果**。

### 3.2 追涨与低吸必须分开观察

市场可能出现：

- 追涨赚钱、低吸也赚钱：全面正反馈；
- 追涨赚钱、低吸失败：核心抱团，扩散不足；
- 追涨失败、低吸赚钱：高低切换或修复阶段；
- 追涨和低吸都失败：负反馈形成的重要证据。

因此产品必须至少形成两条独立反馈链：

- 追涨/接力反馈；
- 低吸/修复反馈。

### 3.3 不同周期不能混成一个市场阶段

指数、全市场、板块、核心股可能处于不同周期。例如：

- 指数仍上涨，但高位连板已经退潮；
- 全市场较弱，但少数主线板块仍在扩张；
- 板块仍强，但核心股已经高位分歧；
- 核心股修复，但跟风股仍持续亏损。

产品应分别给出：

- 指数周期；
- 全市场反馈周期；
- 板块周期；
- 核心股周期。

“市场生命周期”只是这四层信息的归纳，不得覆盖它们之间的背离。

### 3.4 先判断环境，再寻找个股

系统的决策顺序固定为：

```text
市场是否允许做多
→ 哪些策略仍有正反馈
→ 哪些板块正在承载正反馈
→ 板块中的核心与跟随结构是否健康
→ 个股是否满足用户自己的买点
```

市场许可不能替代个股买点，个股结构破坏也不能因为市场仍强而忽略。

## 4. 核心产品模型

### 4.1 三层观察体系

#### 第一层：全市场环境

回答普通股票的典型交易体验：

- 上涨、下跌、平盘数量；
- 涨跌幅中位数；
- 大涨、大跌比例；
- 涨停、跌停数量；
- 成交额和量能变化；
- 指数与个股广度是否背离。

全市场层优先使用中位数、比例和分布，不使用容易被极值影响的均值。

首期纳入沪深京全部 A 股，包括 ST、新股和退市整理股票。由于全市场收盘截面
本身已经返回这些股票，纳入统计不会增加额外接口调用。产品同时输出两个口径：

- **全样本广度**：全部 A 股的真实市场体验；
- **可比样本广度**：单列普通 A 股，排除特殊交易制度带来的阈值差异。

两者使用同一份行情事实，不重复抓取。ST、新股和退市整理还需单独分组展示，
不能先纳入总数、随后又在解释层消失。

#### 第二层：策略参与者反馈

这是产品的核心层。每个交易日收盘后冻结当日群体，下一交易日评价其结果：

| 冻结群体 | 代表的交易行为 | 下一日重点观察 |
|---|---|---|
| 当日涨停 | 打板和持有涨停 | 开盘溢价、收盘收益、可兑现率 |
| 首板 | 启动接力 | 红盘率、二板晋级率、炸板率 |
| 连板 | 高位接力 | 晋级率、断板损失、大回撤率 |
| 强势股池 | 趋势持有和活跃股参与 | 收益中位数、红盘率、退出率 |
| 板块核心 | 核心股参与 | 承接、领涨延续、结构破坏 |
| 炸板股 | 分歧后的承接 | 次日修复率、继续大跌率 |
| 超跌/修复尝试 | 低吸和修复 | 反包率、红盘率、再创新低率 |
| 领跌股 | 负反馈源 | 止跌率、跌停扩散、修复质量 |

群体之间允许重叠，但每个群体必须保存独立成员关系，不能在次日重新计算成员。

#### 第三层：板块与核心载体

回答效应发生在哪里、能否持续：

- 板块赚钱/亏钱强度；
- 板块内部上涨覆盖；
- 龙头、核心、跟风之间是否同步；
- 正反馈是否从单股扩散到梯队；
- 板块的首板、连板和趋势核心是否完整；
- 板块效应连续天数和衰减速度；
- 板块负反馈是否向其他方向扩散。

### 4.2 交易模式跟随赚钱效应

系统不把用户固定为某一种交易者，而是每日并列评价四类模式：

| 模式 | 主要观察群体 | 判断重点 |
|---|---|---|
| 首板/连板接力 | 首板、连板、昨日涨停 | 溢价、晋级、断板损失、可兑现率 |
| 趋势核心 | 强势股池、板块核心 | 趋势延续、回撤、板块承接 |
| 低吸修复 | 炸板、分歧、超跌修复 | 修复率、再创新低率、反包质量 |
| 普涨扩散 | 全市场和板块跟随股 | 广度、中位数、内部一致性 |

每天输出：

- 当前赚钱效应最强模式；
- 次强模式；
- 各模式强度、持续性和数据置信度；
- 模式是否正在从接力切向趋势、从高位切向低吸，或从局部走向普涨；
- 已经失效的模式及其负反馈证据。

“模式跟随市场”不等于追逐当日最高分。只有同时满足正反馈成立、持续性未明显
衰减、负反馈受控的模式，才进入可参与集合。

### 4.3 周期跟随赚钱效应

T+1、T+3、T+5 是统一测量锚点，不是预设持仓周期。系统还需输出：

- 效应年龄：当前正反馈已经连续存在多少个交易日；
- 确认天数：满足确认条件的连续天数；
- 扩散速度：正反馈覆盖的群体和板块是在扩大还是收缩；
- 衰减速度：收益、胜率和承接相对高点下降多少；
- 历史同类状态的持续时间分布；
- 当前处于启动、确认、扩散、高潮还是衰减。

交易周期由状态决定：

```text
效应启动且持续性上升 → 可以继续观察和跟随
效应确认且扩散健康   → 周期自然延长
强度仍高但持续性下降 → 不因过去强势继续延长持有
负反馈形成           → 周期结束，进入持仓检查
```

### 4.4 强度与持续性分离

每种效应都输出两个分数：

| 指标 | 回答的问题 |
|---|---|
| 赚钱效应强度 | 今天正反馈有多强 |
| 赚钱效应持续性 | 这种正反馈未来仍可重复的证据有多少 |
| 亏钱效应强度 | 今天负反馈有多严重 |
| 亏钱效应持续性 | 负反馈继续或扩散的证据有多少 |

典型组合：

| 强度 | 持续性 | 含义 |
|---|---|---|
| 高 | 高 | 已确认并仍在扩散 |
| 高 | 低 | 单日爆发、高潮或脉冲 |
| 低 | 高 | 缓慢累积，尚未完全显性化 |
| 低 | 低 | 暂无清晰效应 |

### 4.5 赚钱效应的四个一级维度

建议首版初始权重如下，后续通过历史验证校准：

| 一级维度 | 初始权重 | 核心事实 |
|---|---:|---|
| 全市场广度 | 25% | 涨跌幅中位数、上涨率、大涨率 |
| 承担风险者回报 | 35% | 昨日涨停/连板/强势池次日收益 |
| 延续质量 | 25% | 晋级、承接、炸板、可兑现 |
| 板块扩散 | 15% | 正反馈板块数、内部覆盖、集中度 |

评分使用滚动历史分位归一化，不直接把某个固定数值永久解释为强或弱。

### 4.6 亏钱效应的四个一级维度

| 一级维度 | 初始权重 | 核心事实 |
|---|---:|---|
| 全市场负面广度 | 20% | 跌幅中位数、大跌率、跌停数 |
| 热门群体负反馈 | 35% | 昨日涨停/连板/核心股大亏比例 |
| 失败烈度 | 25% | 断板、炸板、高开低走、最大回撤 |
| 负反馈扩散 | 20% | 从高位到低位、从单板块到多板块 |

赚钱效应和亏钱效应独立计算，不使用 `loss = 100 - profit`。

### 4.7 持续性评价

赚钱效应持续性由五类证据组成：

1. **兑现稳定性**：T+1、T+3、T+5 的群体收益和胜率是否稳定；
2. **结构延续性**：首板、连板、趋势核心是否保持健康梯队；
3. **板块扩散性**：正反馈是否从核心扩散而不是更加集中；
4. **修复能力**：分歧、炸板和回撤后是否有资金修复；
5. **负反馈约束**：大幅亏损和跌停是否仍被限制在局部。

亏钱效应持续性观察相反方向：

1. 热门群体负收益是否连续；
2. 断板和炸板损失是否继续扩大；
3. 低吸修复是否连续失败；
4. 负反馈是否从高位向中低位扩散；
5. 市场是否缺少新的正反馈载体。

### 4.8 样本结果字段

每个冻结群体至少计算：

- 样本数、有效样本数、数据覆盖率；
- 次日开盘收益中位数；
- 次日收盘收益中位数；
- 次日红盘率；
- 次日大亏率；
- 次日日内最大回撤中位数；
- 一字涨停/跌停比例；
- 可交易、可兑现样本比例；
- 晋级率、断板率、炸板率、修复率；
- T+3、T+5 累计收益中位数和胜率。

建议基础定义：

```text
次日开盘收益 = T+1 open / T close - 1
次日收盘收益 = T+1 close / T close - 1
次日最大回撤 = T+1 low / T close - 1
开盘后收益   = T+1 close / T+1 open - 1
```

“大亏”阈值不应全市场统一写死。首版可按板块涨跌幅限制区分，
并同时保存原始收益，阈值归类只作为展示标签。

### 4.9 市场生命周期

状态机采用以下顺序：

```text
亏钱扩散
→ 亏钱收敛
→ 修复试错
→ 赚钱启动
→ 赚钱确认
→ 赚钱扩散
→ 高潮老化
→ 负反馈预警
→ 负反馈形成
→ 亏钱扩散
```

状态解释：

| 状态 | 识别重点 |
|---|---|
| 亏钱扩散 | 热门和普通股票同时受损，负反馈跨板块扩散 |
| 亏钱收敛 | 大亏和跌停下降，但正反馈尚未建立 |
| 修复试错 | 修复群体开始赚钱，接力反馈仍不稳定 |
| 赚钱启动 | 局部核心率先给出正反馈 |
| 赚钱确认 | 追涨和持有者连续获得可兑现收益 |
| 赚钱扩散 | 正反馈从核心扩散到梯队和更多板块 |
| 高潮老化 | 强度很高，但集中度、炸板或回撤开始上升 |
| 负反馈预警 | 热门群体率先恶化，市场广度尚未全面转弱 |
| 负反馈形成 | 追涨和低吸同时失效，核心结构被破坏 |

状态切换使用滞回规则：

- 普通切换要求连续两日满足，或三项核心证据中至少两项显著越界；
- 极端跌停扩散、核心群体大面积不可兑现等硬风险允许单日切换；
- 当数据覆盖不足时保持原状态并标记“待确认”，不能强制翻转。

### 4.10 负反馈三级预警

| 等级 | 名称 | 识别逻辑 | 产品含义 |
|---|---|---|---|
| L1 | 预警 | 热门群体回报下降、炸板增加、集中度升高 | 停止盲目扩张风险 |
| L2 | 形成 | 热门群体转负、核心走弱、追涨与修复同时恶化 | 新增风险应显著收缩 |
| L3 | 扩散 | 全市场中位数、广度和多板块同步恶化 | 以防守和退出检查为主 |

### 4.11 市场许可

系统不直接给固定仓位，而输出动作边界：

| 许可 | 用户含义 |
|---|---|
| 关闭 | 不新增风险，优先处理持仓 |
| 观察 | 等待负反馈收敛，不因单日反弹追高 |
| 试错 | 仅允许小规模、可快速验证的交易 |
| 选择性开放 | 只参与持续性最强的板块和核心 |
| 开放 | 市场、策略和板块正反馈同时成立 |
| 保护利润 | 强度仍高但持续性下降，停止扩张并保护已有利润 |
| 退出检查 | 市场负反馈形成，逐项检查持仓结构并执行规则 |

“退出检查”不是无条件清仓。最终离场采用两把钥匙：

```text
市场负反馈形成
+ 板块或个股结构破坏
= 执行退出
```

个股出现预设的硬性破坏条件时，可以不等待市场信号。

## 5. 页面与交互方案

### 5.1 首页总览

首屏只展示最重要的信息：

1. 市场许可；
2. 当前生命周期；
3. 赚钱效应强度 / 持续性；
4. 亏钱效应强度 / 持续性；
5. 负反馈预警等级；
6. 当前赚钱模式及效应年龄；
7. 一句话结论和三条关键证据；
8. 数据日期、覆盖率和是否降级。

示例：

```text
市场许可：选择性开放
生命周期：赚钱确认 → 赚钱扩散

赚钱强度 72，持续性 64
亏钱强度 31，持续性 28
当前模式：趋势核心（已确认 4 日，扩散仍在增强）

证据：
- 昨日首板次日收盘收益中位数 +2.1%，红盘率 68%
- 连板晋级率连续两日提升
- 正反馈仍集中在 3 个板块，尚未全面扩散
```

### 5.2 策略反馈矩阵

用二维矩阵展示：

| | 低吸/修复赚钱 | 低吸/修复亏钱 |
|---|---|---|
| 追涨/接力赚钱 | 全面正反馈 | 核心抱团、扩散不足 |
| 追涨/接力亏钱 | 高低切换、修复阶段 | 负反馈形成 |

点击象限可下钻到对应冻结群体及成员。

### 5.3 群体跟踪

每个群体展示：

- T+1 开盘与收盘收益；
- 红盘率和大亏率；
- 晋级/断板/修复；
- T+3、T+5 结果；
- 相对过去 20/60/120 个交易日的分位；
- 成员明细。

默认使用中位数，均值只作为辅助。

### 5.4 板块载体

板块列表分为：

- 正反馈载体；
- 负反馈来源；
- 正在修复；
- 高潮老化；
- 数据不足。

每个板块展示强度、持续性、阶段、内部覆盖、核心股、梯队完整性和负反馈来源。

板块默认覆盖全市场行业和概念，不再以 `is_watched=True` 作为计算范围。
“已关注”只影响用户界面的置顶和订阅，不影响全市场扫描。

### 5.5 历史回放

历史页面允许选择任一交易日，看到当日系统当时能得到的：

- 状态；
- 市场许可；
- 证据；
- 冻结群体；
- 后续 T+1/T+3/T+5 的验证结果。

后验结果必须使用不同视觉样式，避免和当日已知信息混淆。

### 5.6 持仓负反馈检查

当市场进入 L1/L2/L3 负反馈状态时，系统检查交易日志中推导出的未平持仓：

1. 持仓所属交易模式是否仍有赚钱效应；
2. 所属板块是否由正反馈转为衰减或负反馈；
3. 个股是否出现走弱、破位、跌停、核心地位丢失等结构变化；
4. 市场、板块、个股三个层次是否形成共振。

输出三级提示：

| 级别 | 条件 | 展示 |
|---|---|---|
| 提醒 | 市场 L1，但持仓板块和结构仍正常 | 提醒停止盲目加仓，继续观察 |
| 警告 | 市场 L2，且板块或所属模式恶化 | 要求检查止损和退出条件 |
| 紧急 | 市场 L3，且个股结构已经破坏 | 显著警告，列出需要立即处理的证据 |

首期只做站内提示，不自动卖出，也不映射固定仓位。如果交易日志无法可靠推导
当前持仓，必须提示“持仓数据不完整”，不能假装已经完成检查。

## 6. 当前项目能力与关键缺口

### 6.1 可以直接复用的能力

当前项目已经具备：

- 强势股池和涨跌停动态池；
- 个股日 K 线增量拉取和 65 日自举；
- 个股涨跌停、炸板、一字板、连板等事实；
- 全市场涨跌分布和成交额；
- 指数日线；
- 板块、板块成分关系和板块阶段；
- 强势股、龙头、弱转强、交易复盘；
- 盘前和盘后调度、文件锁和失败重试；
- `DailyReview` 历史快照；
- API 降级告警。

### 6.2 现有赚钱效应实现的问题

当前 `/api/market-state/profit-effect` 主要统计“今天仍在强势股池”的股票，
再按前一日状态分组。这会带来：

- 今日已经走弱并退出强势池的股票被排除；
- 群体成员没有按交易日冻结；
- 隔日回报存在幸存者偏差；
- 缺少开盘、最高、最低，无法评价溢价和最大回撤；
- 缺少 T+3/T+5 群体结果；
- 赚钱与亏钱效应仍主要由关注板块的情绪/风险分归纳；
- 缺少持续性和状态转换证据。

### 6.3 外部请求方面的问题

- `sector_top_stocks_service.py` 在查询板块龙头时实时请求东财；
- 外部响应没有统一的请求指纹、日期、校验和与缓存状态；
- 同一数据可能被不同服务以不同方式重复请求；
- 页面接口和同步接口之间尚未建立严格边界；
- 数据表只保留部分 K 线字段，后续计算不得不再次依赖外部源。

### 6.4 数据库迁移问题

项目安装了 Alembic，但 `backend/alembic/versions` 当前为空，
新增字段主要依赖启动时 `_apply_schema_patches()` 的静默 `ALTER TABLE`。

本功能涉及多张新表、索引和唯一约束，必须开始使用正式 Alembic 迁移。
现有补丁机制可以暂时保留兼容，但不应继续承载复杂模型演进。

## 7. 总体技术架构

### 7.1 分层

```text
外部数据源
  ↓
Source Adapter（来源适配与字段标准化）
  ↓
Fetch Coordinator（去重、锁、缓存、重试、降级）
  ↓
Fact Repository（行情事实、冻结群体、板块关系）
  ↓
Effect Engine（群体结果、评分、持续性、状态机）
  ↓
Materialized Result（每日市场/板块/群体结果）
  ↓
FastAPI 只读接口
  ↓
React 展示与历史回放
```

硬性边界：

- Router 不直接调用外部行情；
- 页面请求不触发外部行情；
- Effect Engine 不调用外部行情；
- 所有外部数据先标准化并持久化；
- 所有结果支持按交易日重复计算；
- 所有计算记录 `formula_version`。

### 7.2 一次采集、多处复用

每日统一构建 `tracked_universe`：

```text
当日强势股池
∪ 当日涨停/跌停/炸板
∪ 前一交易日全部冻结群体
∪ 仍在 T+3/T+5 观察期的历史群体
∪ 全市场关键板块核心股
∪ 用户持仓和关注股
∪ 退出强势池、等待复核的股票
```

对集合去重后，每只股票只执行一次增量 K 线同步。

全市场板块采用两层扫描：

1. **全量轻扫描**：每天分页获取全部行业/概念板块的涨跌、成交额、换手和多周期
   涨幅，保证每个板块都进入排序和状态初筛；
2. **重点深计算**：对活跃、快速升温、快速恶化、持仓相关和效应排名靠前的板块，
   使用本地成员关系计算内部广度、核心/跟随和群体反馈。

板块成员关系是慢变化数据，采用缓存、增量更新和轮换校验，不每天反向遍历约
全部板块抓取所有成分股。现有 `sync_boards.py` 的板块元数据分页能力可以复用；
逐板块查询成分数量和逐股 F10 查询必须纳入每日请求预算，不能无上限执行。

### 7.3 外部请求协调器

新增统一组件 `ExternalFetchCoordinator`，请求唯一键：

```text
(source, endpoint_key, trade_date, params_hash)
```

能力：

- 单次任务内 single-flight：相同请求只有一个实际调用；
- 跨任务幂等：已有完整结果不重复请求；
- 按交易日冻结：盘后最终数据默认永久有效；
- 请求级锁：防止手动任务与调度任务重复抓取；
- 指数退避和最大重试；
- 主源、备源切换；
- 响应校验和与行数检查；
- 数据日期校验，防止盘前把前一日数据写入当天；
- 记录失败原因、耗时和降级状态；
- 支持管理员显式 `force_refresh`，普通查询无此能力。

协调器同时维护每日来源预算。预算接近阈值时依次保留：

```text
全市场截面
→ 全市场板块轻扫描
→ 持仓相关板块
→ 正负反馈候选板块
→ 普通板块成员轮换校验
```

被跳过的只是深度成员刷新，不是板块轻扫描；因此仍能观察全市场板块，同时避免
因一次任务发起数百个详情请求而被限流。

### 7.4 缓存策略

| 数据类型 | 盘中 TTL | 盘后策略 |
|---|---:|---|
| 交易日 | 24 小时 | 按日期永久缓存 |
| 全市场截面 | 1–5 分钟 | 收盘最终版永久保存 |
| 强势/涨跌停池 | 1–5 分钟 | 按交易日冻结 |
| 个股日 K | 当日 5 分钟 | 历史日期永久保存 |
| 板块元数据/成分 | 1 天 | 内容校验和不变则不写 |
| 板块排名 | 不单独外部查询 | 每日由本地事实物化 |
| 市场效应结果 | 不使用时间 TTL | 由输入版本决定是否重算 |

首期只要求盘后 EOD，盘中 TTL 作为后续扩展能力。

### 9.2 建议新增接口 A：全市场收盘截面

**优先级：P0，建议新增，但复用现有东财 clist 能力，不引入新的供应商。**

一次请求保存沪深京 A 股收盘截面：

```text
代码、名称、最新价、涨跌幅、成交量、成交额、振幅、
最高、最低、今开、昨收、换手率、总市值、流通市值
```

价值：

- 得到真实的全市场涨跌幅中位数和分位数；
- 不只依赖十档涨跌分布；
- 全市场 OHLC 一次返回，避免逐股 K 线；
- 支持高开低走、大幅回撤和收益分布；
- 可同时完成股票名称/ST 状态校验。

AKShare 的 `stock_zh_a_spot_em` 是同类东财全市场接口的现成适配，
文档说明单次返回全部沪深京 A 股及上述字段。项目可直接扩展现有
`fetch_main_board_stocks()`，不必为了这一能力整体引入 AkShare。

调用策略：

- 盘后只调用一次；
- 结果按交易日保存为最终截面；
- 失败时使用现有涨跌分布 + 跟踪集合 K 线降级；
- 不在每次页面加载时调用。

### 9.3 建议新增接口 B：结构化涨停池

**优先级：P1，建议作为质量增强和交叉校验，不作为首版唯一权威源。**

建议接入：

- 当日涨停池；
- 昨日涨停池；
- 炸板池；
- 跌停池。

可获得当前智能选股与日 K 不稳定提供的字段：

```text
首次封板时间
最后封板时间
炸板次数
封板资金
连板数
昨日连板数
连续跌停
开板次数
所属行业
```

价值：

- 更准确地区分首板、连板、炸板；
- 计算封板质量和可兑现性；
- 对现有智能选股结果交叉验证；
- 减少靠价格阈值反推涨跌停状态的脆弱性。

约束：

- 这些接口只提供近期数据，必须每日落库；
- 上游结构容易变化，必须经过 Adapter；
- 接口失败不能阻断主流程；
- 仍以本地冻结群体为历史事实。

### 9.4 暂不新增的接口

| 接口类型 | 原因 |
|---|---|
| 第三方“赚钱效应指数” | 黑盒口径，无法验证，且与本产品重复 |
| 每只股票的实时行情接口 | 全市场截面和跟踪集合 K 线已经足够 |
| 全市场分钟线 | 成本高，首期日级判断不需要 |
| 资金流向/主力净流入 | 口径不稳定，首期不作为核心证据 |
| 新的板块成分供应商 | 现有东财板块与 F10 已能覆盖 |
| 页面级板块龙头实时接口 | 改为盘后本地计算，不应继续外部请求 |
| Legulegu 市场活跃度 | 与现有市场宽度重复，且新增供应商依赖 |

### 9.5 对外部依赖的最终数量控制

首期每个交易日新增的外部请求：

- 全市场收盘截面：1 个逻辑请求，必要时按分页完成；
- 结构化涨停/昨日涨停/炸板/跌停池：最多 4 个逻辑请求，P1 才启用。

不会新增“全市场股票数 × K 线”的请求量。

现有 K 线请求只针对去重后的跟踪集合，并优先用数据库补齐历史。

全市场板块不等于每天抓取所有板块的全部成分股。每日全量板块行情继续复用现有
分页接口；成员关系从本地缓存读取，只对变化概率高或交易相关的板块增量校验。

## 10. 盘后完整处理流程

建议将 `daily_update.py` 拆成可重入的步骤，每步有输入校验和运行记录：

### Step 0：确定交易日

- 获取并缓存有效交易日；
- 校验目标日期和外部响应日期；
- 非交易日不创建错误快照。

### Step 1：同步全市场收盘截面

- 调用一次全市场接口；
- 标准化字段；
- 过滤 B 股、基金等非目标证券；
- 持久化全市场截面或最少聚合事实；
- 生成宽度、中位数和收益分布；
- 标记数据覆盖率。

### Step 2：同步动态池

并行获取：

- 强势股池；
- 涨跌停池；
- P1 的结构化涨停/炸板/跌停池。

每个接口只调用一次，并记录 `external_fetch_runs`。

### Step 3：构建跟踪集合

合并：

- 当日动态池；
- 昨日冻结群体；
- 尚需计算 T+3/T+5 的群体；
- 全市场关键板块核心；
- 用户关注和持仓；
- 退出池复核股票。

记录每只股票进入集合的原因，方便排查。

### Step 4：统一增量同步 K 线

- 数据库已有足够历史：只取缺失日期；
- 新股票：一次获取约 65 日并自举；
- 相同股票不被多个业务模块重复请求；
- 保存完整 OHLCV 和数据源；
- 对主源、备源差异做质量标记。

### Step 5：写入当日股票与板块事实

- 更新涨跌停、炸板、一字板和连板；
- 更新板块关系和主板块；
- 刷新板块统计、阶段、排名；
- 物化板块核心股，替代页面实时抓取。

### Step 6：评价历史冻结群体

- 对 T-1 群体生成 horizon=1 结果；
- 对 T-3 群体生成 horizon=3 结果；
- 对 T-5 群体生成 horizon=5 结果；
- 数据不足则标记 partial，不补零。

### Step 7：冻结当日群体

根据当日收盘已知事实生成各 cohort。

先评价历史群体，再冻结当日群体，避免逻辑混淆。

### Step 8：计算市场和板块效应

依次计算：

1. 原始维度；
2. 滚动分位标准化；
3. 赚钱/亏钱强度；
4. 赚钱/亏钱持续性；
5. 负反馈等级；
6. 生命周期；
7. 市场许可；
8. 证据和摘要。

### Step 9：保存物化结果

- 写入新结果表；
- 回写 `DailyReview` 兼容字段；
- 保存 `formula_version` 和 `input_checksum`；
- 相同输入重复执行得到相同结果。

### Step 10：数据质量检查

至少检查：

- 全市场覆盖率；
- 群体有效样本率；
- 响应交易日；
- 价格字段一致性；
- 极端数量与动态池差异；
- 是否使用备源；
- 是否存在部分结果。

仅在质量通过后把当日结果标记为 final。

## 11. 计算引擎设计

### 11.1 标准化

初期使用过去 120 个有效交易日的经验分位：

```text
normalized = percentile_rank(current_value, history_120d)
```

优点：

- 适应不同市场波动阶段；
- 避免固定阈值在 10%、20%、30% 涨跌幅股票之间失真；
- 分数含义更稳定；
- 便于历史验证。

不足 20 个交易日时：

- 不输出正式持续性分；
- 使用配置中的保守默认阈值；
- 显示“样本积累中”。

### 11.2 稳健统计

- 群体中心值优先用中位数；
- 均值需要 5% Winsorize 后再计算；
- 小于最小样本量的群体不进入综合分；
- 一字板样本单独展示，不与可自由交易样本直接混合；
- ST、退市整理、新股是否纳入由统一市场范围配置决定；
- 同一股票可属于多个解释性群体，但全市场汇总只计一次。

### 11.3 可解释证据

每个得分维度保存：

```json
{
  "metric": "previous_limit_up_close_return_median",
  "raw_value": 2.1,
  "sample_size": 38,
  "history_percentile": 76,
  "direction": "positive",
  "contribution": 8.4
}
```

一句话结论只从结构化证据模板生成，不允许脱离事实自由编写。

### 11.4 公式版本

建议格式：

```text
market_effect_v1.0.0
```

- 调权重：minor；
- 改指标定义或样本范围：major；
- 只修复不改变结果含义的实现错误：patch。

历史结果默认不静默覆盖。重算后保留版本，页面可选择当前口径。

## 15. 数据回填方案

### 15.1 可以回填的内容

现有数据库可回填：

- 历史强势股快照；
- 历史涨跌停、炸板和阶段；
- `DailyReview` 市场宽度；
- 指数和板块快照；
- 已保存股票的收盘收益；
- 一部分 T+1 群体结果。

### 15.2 无法可靠回填的内容

如果历史没有保存：

- 当日冻结的完整强势池成员；
- 退出池的失败样本；
- 开盘、最高、最低；
- 首次/最后封板时间；
- 炸板次数；

则不能用今天的状态反推历史。

处理方式：

- 标记 `quality_status=partial`；
- 不进入正式评分回测；
- 不伪造为完整数据；
- 从功能上线日起开始积累高质量正式样本。

### 15.3 推荐回填范围

- 首先回填最近 120 个交易日；
- 完整质量数据从上线日记为 `gold`；
- 历史不完整数据记为 `silver/partial`；
- 评分分位初期可以使用 silver 数据，但验收报告必须区分质量。

## 16. 分阶段实施

### Phase 0：数据地基

目标：不改主要页面，先获得可信事实。

- 启用 Alembic；
- 扩展 OHLCV 字段；
- 建 `external_fetch_runs`；
- 建冻结群体表；
- 接入全市场收盘截面；
- 沪深京全部 A 股进入全样本广度，并生成特殊股票分层；
- 全市场行业/概念板块轻扫描；
- 构建统一跟踪集合；
- 消除板块龙头查询时外部调用；
- 加入去重与质量测试。

验收：

- 同一日重复运行不会重复请求已完成数据；
- 页面查询期间外部请求数为 0；
- 昨日群体成员不会随今日状态变化；
- 每日任务可安全重跑。

### Phase 1：最小可用产品

目标：回答“现在能不能做”和“谁在赚钱/亏钱”。

- 首板、连板、强势池、板块核心、炸板和修复尝试等核心 cohort；
- T+1 开盘/收盘/回撤反馈；
- 接力、趋势、低吸修复、普涨扩散四种模式排名；
- 效应年龄、增强/衰减和当前主导模式；
- 赚钱/亏钱强度；
- L1/L2/L3 负反馈；
- 生命周期和市场许可；
- 首页总览、反馈矩阵、群体下钻；
- 负反馈与持仓检查站内警告；
- 旧接口兼容。

验收：

- 每个结论有证据；
- 数据不足时明确降级；
- 无幸存者偏差；
- 状态机不会频繁反复。

### Phase 2：持续性与板块载体

目标：回答“效应能持续多久、应该聚焦哪里”。

- T+3/T+5；
- 赚钱/亏钱持续性；
- 板块效应与核心/跟随结构；
- 历史同类效应持续时间分布；
- 高潮老化；
- 结构化涨停池 P1；
- 历史回放与后验验证。

### Phase 3：个人交易闭环

目标：验证用户是否在正确环境做正确交易。

- 交易日志关联当日市场许可；
- 标记用户交易属于追涨、低吸、趋势还是修复；
- 分析个人策略在不同市场状态下的胜率；
- 输出“环境错配”而不是泛化的盈亏归因；
- 支持用户自定义风险阈值和许可映射。

## 17. 验证与防止自我欺骗

### 17.1 禁止未来数据泄漏

- T 日群体只能使用 T 日收盘前已知事实冻结；
- T+1 结果不得反过来修改 T 日成员；
- 历史板块归属应优先使用当时快照；
- 公式校准分训练区间和验证区间；
- 页面上明确区分“当时信号”和“后验结果”。

### 17.2 评价指标

不是只比较指数涨跌，应比较：

- 市场许可不同等级下的 T+1/T+3/T+5 群体收益；
- 负反馈等级后的最大回撤；
- 状态切换次数与平均持续天数；
- 预警领先负反馈扩散的天数；
- 假预警比例；
- 数据降级日与正常日的差异；
- 各策略群体的独立表现。

### 17.3 上线门槛

建议至少积累 60 个完整交易日后首次校准，120 日后评估稳定性。
在此之前，分数标注为 beta，原始事实优先于综合评分。

## 18. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 东财非正式接口变化 | 字段或返回结构失效 | Adapter、契约测试、备源、降级 |
| 近期股池接口无法补远期历史 | 回测不完整 | 每日冻结，历史标记 partial |
| 小样本群体波动大 | 分数失真 | 最小样本、置信度、贝叶斯收缩或不评分 |
| 重复群体导致重复解释 | 用户误解 | 解释层允许重叠，市场层去重 |
| 状态频繁切换 | 交易噪声 | 滞回、连续确认、硬风险例外 |
| 公式过拟合 | 历史漂亮、实盘失效 | 简单指标、版本化、走样本外验证 |
| 数据源之间结果冲突 | 状态不可信 | 来源优先级、差异阈值、质量标记 |
| 任务部分成功 | 页面混用不同日期 | final 标记、输入校验和、原子发布 |

## 19. 已确认的产品决策

### 19.1 全市场范围

- 首期覆盖沪深京全部 A 股；
- ST、新股、退市整理全部进入全样本广度；
- 同时提供普通 A 股可比口径和特殊股票分组；
- 所有口径复用同一份全市场截面，不增加外部请求。

### 19.2 模式由市场决定

- 用户不固定为首板、连板、趋势或低吸交易者；
- 系统每天比较各模式真实反馈；
- 输出当前主导模式、次强模式、轮动方向和已经失效的模式；
- 只有强度、持续性和风险约束同时成立，模式才获得参与许可。

### 19.3 周期由效应决定

- 不预设固定持有天数；
- T+1/T+3/T+5 只作为统一测量锚点；
- 实际周期依据效应年龄、扩散、衰减和负反馈决定；
- 高强度但低持续性不能被解释为应该延长周期。

### 19.4 首期只给动作边界

- 输出关闭、观察、试错、选择性开放、开放、保护利润和退出检查；
- 首期不映射固定仓位；
- 后续再结合个人风险承受能力增加自定义仓位区间。

### 19.5 全市场板块扫描

- 每天轻量扫描全部行业和概念板块；
- 对关键板块使用本地成员缓存做深度计算；
- 成员关系按请求预算增量更新和轮换校验；
- `is_watched` 只影响置顶，不再限制市场效应计算范围。

### 19.6 负反馈联动持仓

- L1/L2/L3 负反馈均触发对应级别的持仓检查；
- 检查市场、交易模式、板块和个股四层证据；
- 首期提供站内提醒、警告和紧急提示；
- 不自动交易，不提供没有证据的清仓结论。

```text
8. 负反馈状态机与市场许可
9. 首页和证据下钻
10. T+3/T+5 持续性
11. 板块载体
12. 交易日志闭环
```

不建议先做复杂页面再补数据，也不建议先调一个漂亮的综合分。
首个可验证成果应是：

> 任意选择一个交易日，都能准确看到前一交易日各类参与者在当天的真实反馈，
> 并且这些成员、行情和计算不依赖当天页面查询。
