# 板块趋势 · 主升板块雷达（sector_mainline_v1）

> 2026-09-13 上线。页面：V1「板块趋势」（侧边栏顶层，大盘趋势下面，路由 `/sector-trend` 不变）。
> 代码：`backend/app/services/sector_mainline_service.py`（规则）、`backend/app/routers/sector_trend.py`（接口）、
> `backend/scripts/sector_mainline.py`（命令行）、`frontend/src/pages/SectorTrend.tsx`（页面）。
> 测试：`backend/tests/test_sector_mainline.py`。
>
> **第一版是规则型状态机，阈值是工程初始值**：第七节的分位数只用来定量级（板块指数不是个股），
> 不代表已经拿历史回测优化过。

## 一、回答什么

在「**大盘 → 板块主线 → 个股**」这条链上管中间那一环：**现在哪几个板块在主升。**
页面顶部一行「主线（加速 + 主升）」加八张状态卡，十秒内能答出来。

**主升状态 ≠ 买入信号。** 这里只描述板块处在什么状态，不给买卖建议。

做法是 **事实 → 闸门 → 状态 → 证据**：每个关注板块过四道闸，每道闸给 PASS / WARN / FAIL /
UNKNOWN 和它依据的事实，状态由闸门组合决定。**不打分、不接 AI**——页面上从状态能一路点到
「为什么是这个状态」。

## 二、数据从哪来

| 事实 | 来源 | 说明 |
|---|---|---|
| 趋势：MA5/10/20、MA20 五日走向、偏离 MA20、5 日涨幅、收盘 20 日新高 | `SectorIndexDaily.close` | 生产上 302 个关注板块历史齐全（约 300 根） |
| 相对强度：RS5/10/20、RS10 在关注板块里的名次 | 板块指数 vs 上证 000001 | 复合收益，锚点按上证交易日往前数；`relative_strength_service.rs_vs_benchmark`，跟 RS_market 同一套口径 |
| 生态：每日涨停只数、最高连板、炸板、跌停、上涨家数 | 成分股日快照 × 成分关系 | 一条分组查询；跟买入检查的「板块涨停数」**同一个口径** |
| 成交额：5 日 / 20 日 | `SectorIndexDaily.amount` | 缺了就跳过用到它的两条事实（放量滞涨、情绪高潮），写进证据 |

**刻意不用的：**

- **SectorDailySnapshot**。2026-09-13 看生产数据：只有 08-21 以来 16 天；`board_height` 几乎恒为 0
  （它只数强势池成员——元件 09-07 涨停 13 只，高度记 0）；`strong_stock_count` 是当时强势池成员数的拷贝，
  16 天基本不动；`limit_up_count` 跟成分股口径会「7 对 2」打架（数据新鲜度契约第 6 条）。
- **emotion_score / leader_score / risk_score / phase**：自造的黑箱分数。
- **Sector.rank_\***：只给前 5 名打标，其余都是 NULL。名次在这里按全体关注板块现算。
- **「强势股数量」**：强势池没有逐日历史（快照里没有这个标志），拿当前成员数冒充历史就是上面那个坑。

## 三、状态基准日

页面顶部「状态基准：YYYY-MM-DD 收盘」。取最近一个同时满足下面三条的交易日：

1. 关注板块里一半以上有这天的板块指数 bar（sync_boards 只在**收盘后**写，盘中不写）；
2. 这天已经收盘（`bar_is_settled`）；
3. 这天的成分股快照**过半**已结算。盘前 09:27 那一跑写的是 0/N，所以盘中、盘前的数据不会让基准日前移。

没用 `settled_by_date` 的「一票否决」：生产上 09-04 ~ 09-10 每天都有少数行没结算（收盘那一跑没拉到），
严格口径下过去的交易日全是 False，生态就全成了 UNKNOWN。那几只照实写进板块的证据
（「N 只成分股当天的快照不是收盘终值，涨停数可能不全」）。比例口径是 `snapshot_settlement.settlement_counts`。

## 四、四道闸

| 闸 | PASS | WARN | FAIL | UNKNOWN |
|---|---|---|---|---|
| 趋势 | MA5 > MA10 > MA20，MA20 五日向上，收盘 ≥ MA10 | 站在 MA20 上方，但上面三条缺一 | 收盘 < MA20 | 那天没有 bar，或不足 26 根 |
| 相对强度 | RS10 > 0 且 RS20 > 0，RS10 排关注板块前 20% | RS10 > 0，但 RS20 ≤ 0 或名次不够 | RS10 ≤ 0 | 上证缺那天，或锚点那天板块缺 bar |
| 生态 | 近 3 日涨停合计 ≥3、至少 2 天有涨停、出过 2 板，涨停不在收缩、不是单日爆发、高度不在降 | 近 3 日合计 ≥2 但上面缺一条 | 近 3 日合计 ≤1 | 近 3 日有一天没有成分股快照，或没有成分关系 |
| 风险 | 没有过热、没有见顶迹象 | 偏离 MA20 ≥8%；或极端乖离但没有见顶迹象；或出现见顶迹象但不极端 | 高潮：极端乖离 + 至少一个见顶迹象，或极端乖离 + 涨停（近 3 日 ≥10 只）和成交（5 日 / 20 日 ≥1.4 倍）同时极端；跌停潮：跌停 ≥3 只且不少于涨停 | 趋势事实缺失 |

- **极端乖离**：偏离 MA20 ≥12% 或 5 日涨幅 ≥12%。
- **见顶迹象**：涨停收缩；封板率 <50%（涨停 + 炸板 ≥4 只）；指数当日 ≤ -2%；跌停 ≥2 只；
  放量滞涨（5 日 / 20 日成交额 ≥1.4 倍且当日涨幅 ≤0.5%）。

## 五、涨停趋势

看 D-5 ~ D 六天的成分股涨停只数，按顺序判：

| 标签 | 条件 |
|---|---|
| 未知 | 六天里有一天没快照 |
| 单日爆发 SPIKE | 当天 ≥4 只，前两天合计 ≤1 只 |
| 收缩 CONTRACTING | 前 3 日 ≥3 只，近 3 日 ≤ 前 3 日的 60% |
| 扩散 EXPANDING | 近 3 日 ≥3 只、比前 3 日多、至少 2 天有涨停 |
| 平稳 STABLE | 其余 |

高度在降：前 3 日最高 ≥3 板，近 3 日最高掉了 2 板以上。

## 六、状态

核心条件 = 趋势、相对强度、生态三道闸全 PASS。「主升过」= 最近 5 天当过主升 / 加速 / 高潮。
状态按天往前推 10 天（滞回要用前一天的状态），从上往下判：

| 状态 | 条件 |
|---|---|
| 未知 | 趋势 UNKNOWN；或趋势没 FAIL 但相对强度 / 生态 UNKNOWN |
| 转弱 / 无 | 趋势 FAIL、相对强度 FAIL、或跌停潮：主升过 → 转弱，否则 → 无 |
| 高潮 | 风险 FAIL（见第四节） |
| 转弱 | 主升过，且「收盘跌破 MA10 + 近 5 日跑输上证 + 涨停收缩或断档」同时出现——还没跌破 MA20 也算 |
| 加速 | 核心条件今天满足，主升过（或近 3 天 2 天满足），且偏离 MA20 ≥8%、5 日 ≥6% |
| 主升 | 核心条件今天满足，主升过（延续），或近 3 天里有 2 天满足（**滞回：一天不算**） |
| 点火 | 核心条件今天**第一次**满足，还差一天确认 |
| 分歧 | 昨天在主线里且主升过，今天核心条件没全过——**主升里掉一天先记分歧**；或 K 线还强（趋势、相对强度都 PASS）但生态在退（涨停收缩或高度在降，且前 3 日 ≥3 只） |
| 无 | 其余。只过了两道闸的、单日涨停爆发的也在这里，理由里写着差哪一道 |

「在主线里」= 主升、加速、高潮、分歧。

**分歧不续命**：最后一次主升 / 加速 / 高潮过去 5 天，就不再挂分歧、也不再算转弱。第一版拿「在主线里」（含分歧）判，
主升过一次的板块会一直挂在分歧上、跌破 MA20 又变转弱——用生产同源数据回放，09-11 有 46 个「转弱」、每天三四十个
「分歧」，真正的主线反而被淹没。

**点火只留「第一次全过」**（2026-09-13 看过生产分布后用户定的）。第一版「三道闸过了两道」「单日涨停爆发」也记点火，
生产上一天出过 41 个。用生产同源数据回放 10 天，看每种点火第二天变成什么：

| 点火的来源 | 次数 | 次日进主升 / 加速 | 次日回到「无」 |
|---|---|---|---|
| 三道闸第一次全过 | 38 | 50% | 18% |
| 两道闸过了（三种组合合计） | 156 | 2% | 54% |
| 单日涨停爆发 | 18 | 0% | 61% |

默认排序：加速 > 主升 > 点火 > 高潮 > 分歧 > 转弱 > 无 > 未知，同状态按 RS10 降序 → 5 日涨幅名次 → 近 3 日涨停降序。

## 七、阈值的出处（先量再改）

**板块指数的波动远小于个股，阈值必须是板块量级的。** 2026-09-13 用 282 个板块的日 K（导出文件，
跟生产同源）× 最近 20 个交易日、上证取生产 `/api/market-trend/indices` 实测：

| 指标 | 「均线多头 + RS10、RS20 双正」样本（2014 个板块-日） |
|---|---|
| 偏离 MA20 | p50 5.4%，p90 8.9%，p95 10.2%，p99 12.9% |
| 5 日涨幅 | p50 2.8%，p90 6.8%，p95 8.6%，p99 12.6% |
| RS10 | p50 5.2，p90 11.0，p99 17.2 个百分点 |
| 5 日 / 20 日成交额 | p50 1.02，p90 1.23，p99 1.45 |

所以：偏热 / 加速取 p90（偏离 8%、5 日 6%），极端取 p99（12%），放量取 1.4 倍。
「均线多头 + RS 双正」每天 8 ~ 188 个板块，普涨日太宽，所以相对强度还要求 RS10 排前 20%、再叠加生态。

情绪高潮的「近 3 日涨停 ≥10 只」取自涨停板块雷达 08-25 以来的历史：有涨停的板块-日里，近 3 日涨停和
p5 = 11、p10 = 8。那份历史每天只给 40 张卡，只能定个量级。

| | 加速 | 主升 | 点火 | 高潮 | 分歧 | 转弱 | 无 | 未知 |
|---|---|---|---|---|---|---|---|---|
| 2026-09-11 | 1 | 2 | 6 | 0 | 7 | 16 | 268 | 2 |
| 最近 10 个交易日 | 0 ~ 2 | 2 ~ 13 | 6 ~ 41 | 0 | 7 ~ 37 | 0 ~ 16 | 218 ~ 268 | 2 |

主升 + 加速每天 3 ~ 14 个，在预期之内；09-11 的主线是元件、铜缆高速连接、光纤概念，跟回放一致。
点火太多，于是收窄（见第六节）。**高潮 10 天里一次都没触发**：一是这段没有乖离、涨停、成交同时极端的板块，
二是那几天的成交额还是空的，放量滞涨、情绪高潮两条判断不了。补数之后再看。

## 八、跟 ChatGPT 方案的取舍

| 方案里的 | 结论 | 理由 |
|---|---|---|
| 事实 → Gate → 状态 → 证据，不要黑箱分 | 采纳 | 跟仓库「打分不可信」的结论一致 |
| 四道闸、八种状态、涨停趋势五类、滞回 | 采纳 | 阈值换成板块量级的实测值 |
| Case 2：趋势未确认时的单日涨停爆发 → 点火 | **先采纳，看过生产分布后撤掉** | 回放里单日爆发 18 次、次日进主升 0 次；「不判主升」这条仍然成立，只是记「无」 |
| Case 5：涨停 / 成交 / 偏离同时极端 → 高潮 | 采纳，另外保留「极端乖离 + 见顶迹象」 | 两种都是高潮：一种是情绪冲到顶，一种是已经出现裂缝 |
| Case 6：跌破 MA10 + RS5 < 0 + 生态收缩 → 转弱 | 采纳 | 只在主升过时成立；单独跌破 MA10 仍是分歧（主升里正常回踩一天就会破 MA10） |
| Case 1 的「MA10 向上」「RS5 / RS10 > 0」 | 改 | 用 MA20 走向、RS10 / RS20：板块指数日波动小，MA10、RS5 太灵敏，主升里回踩一天就翻 |
| 生态用 SectorDailySnapshot | **不采纳** | 见第二节：16 天、高度恒 0、强势股数是常数、跟成分口径打架。改用成分股日快照 |
| 性能一节「批量查 SectorDailySnapshot」 | 不需要 | 新模块不读这张表 |
| 排序里的 rank_5d | 改 | rank_5d 只有前 5 名；换成全体关注板块现算的 5 日涨幅名次 |
| 风险闸用 risk_score | **不采纳** | 黑箱分。只用乖离、封板率、跌停、成交额这些看得见的事实 |
| 强势股数量进生态闸 | **不采纳** | 没有逐日历史 |
| 给 SectorDailySnapshot 加可空字段 | **不做** | 新模块不读这张表，加了就是没人用的列；也就没有数据库 migration |
| sync_boards 从 clist 顺手写开高低量额 | 采纳 | 零新增请求；字段含义 09-11 跟 push2his 日 K 逐字段核对（65 个板块 × 6 个字段，0 处不一致） |
| 列表轻量、详情才带序列 | 采纳 | 列表查询条数固定（有测试盯着） |
| 前端拆成五个组件文件 | 不拆 | 方案自己也说「不要为了结构过度拆文件」；页面一个文件、按区块分函数 |
| 侧边栏把板块趋势提到顶层 | 采纳 | 情绪板块留在「板块分析」 |
| 传统多周期排名保留 | 采纳 | 折叠在页面底部，展开才加载（它要拉 2.1MB 的全量板块） |
| 不 commit、不 push | 不采纳 | 用户的常设要求是验证后提交推送 |

## 九、数据补充

1. **sync_boards**：clist 请求加 `f5,f15,f16,f17`（成交量、最高、最低、开盘），收盘后连同已有的 `f6`
   成交额一起写进 SectorIndexDaily。盘中不写；clist 给 `-` 的字段不写，也不拿空值盖掉已有的值。
2. **导入补空字段**：09-13 之前 sync_boards 只写收盘和涨跌幅，最近那几天的开高低量额是空的。
   `import_sector_klines` 现在对「库里已有、但这些字段是空的」行，只要两边收盘对得上（差 ≤0.05%）就补空字段，
   已有的值一律不覆盖；收盘对不上一个字段都不动（计 mismatch）。已经导入过的文件在 `data/inbox/done/`，再导一次即可
   （09-13 生产试跑：282 个板块，补齐空字段 1691 行，收盘对不上 0 行）：

   ```bash
   cd /opt/code/tradeflux/backend
   .venv/bin/python scripts/import_sector_klines.py data/inbox/done/<文件名>.jsonl --dry-run
   .venv/bin/python scripts/import_sector_klines.py data/inbox/done/<文件名>.jsonl
   ```

   没在那份文件里的板块，最近几天的成交额会一直空到 20 个交易日滚过去——那期间放量滞涨、情绪高潮两条跳过，
   证据里会写。

## 十、上线后核对

```bash
cd /opt/code/tradeflux/backend
.venv/bin/python -m scripts.sector_mainline              # 分布 + 各状态名单，最后一行列出未知的原因
.venv/bin/python -m scripts.sector_mainline --days 10    # 最近 10 天每天的分布：主升 + 加速应是个位数到十几个
.venv/bin/python -m scripts.sector_mainline --code BK0459
```

三条手工核对：

1. **单日涨停爆发不误判主升**：找当天涨停多、前两天几乎没有的板块，应该是「无」，理由里写着单日爆发
   （例：商业航天 09-11 涨停 8 只，还跌破了 MA20）。
2. **K 线好、涨停和高度在退 → 分歧**：`--code` 看它近 10 天，主升之后生态闸变 WARN 那天起应是分歧
   （例：PCB 09-11，涨停前 3 日 20 → 近 3 日 11）。
3. **十秒答出主升板块**：打开页面，顶部那行「主线（加速 + 主升）」就是答案。

## 十一、已知局限

- 成分用的是**现在的**成分关系，历史上调进调出的不回溯（幸存者偏差）。
- 全部板块都跟上证比。以创业板股票为主的板块天然波动大，RS 会偏大；名次是在同一把尺子下比的，排序仍有意义。
- 方案里的「Leader 梯队」只体现在最高连板和涨停序列上，没有做龙头识别——那要依赖龙头分，而龙头分是黑箱。
- 弱转强雷达的板块闸（`w2s_sector_gate_service`）还在用旧的 phase 分类，没接这一套——改它会改变弱转强的行为，
  不在这次范围里。
