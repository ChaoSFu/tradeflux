# 大市值概览（Large Cap Monitor）

> 2026-11-08 上线 V1。页面 `/large-cap`（活跃股分析 → 大市值概览，要登录）。
> 代码：`backend/app/services/large_cap_sync_service.py`（采集）、`large_cap_service.py`（统计）、
> `backend/app/routers/large_cap.py`（接口）、`backend/scripts/large_cap_sync.py`（命令行）、
> `frontend/src/pages/LargeCapOverview.tsx`。

**定位**：用行情和市值事实观察权重股和行业方向。不推断机构净流入，不造强度分 / 资金分 / 热度分，
不接买入闸门，不出交易信号。

## 一、数据从哪来

东财 clist 全市场列表（`push2delay`，失败换 `push2`），四个市场分组：沪主板、科创板、深主板、
创业板。**不含北交所**。按总市值降序翻页，**单页上限 100 条**（pz=200/500 也只回 100），
全市场约 5563 只、58 页，本机实测 2~4 分钟。

### 字段口径（2026-11-08 对 10 只股票逐个核对，全部与东财前复权日 K / 个股详情一致）

| 字段 | 含义 | 单位 / 备注 |
|---|---|---|
| f20 | 总市值 | 元，存亿元。= 总股本 × 最新价；A+H 公司的总股本含 H 股（工行 30080 亿） |
| f21 | 流通市值 | 元，存亿元 |
| f2 / f3 | 最新价 / 当日涨跌幅 | 元 / % |
| f6 | 成交额 | 元，存亿元（= 日 K f57） |
| f8 | **换手率** | %（= 日 K f61） |
| f10 | **量比** | 收盘后 = 当日成交量 ÷ 前 5 日均量 |
| f109 / f160 / f110 / f24 | 近 5 / 10 / 20 / 60 个交易日涨跌幅 | %，前复权收盘价算 |
| f100 | 东财二级行业 | 跟 sectors 表的行业板块同名（≥400 亿的 435 只全对得上） |
| f103 | 概念 | 逗号分隔的板块名，跟 sectors 表的概念板块同名。只有题材概念，不含 F10 里混着的权重股 / HS300_ / 融资融券这类风格、指数板块 |
| f26 | 上市日 | |
| f297 | 交易日 | 快照日期以它为准，不用本机日期 |

**两个坑**：

- `eastmoney_fetcher._fetch_from_eastmoney`（股票列表的备用路径）把 **f10 当换手率**用了，那是量比。
  而且它请求 pz=200、看到不满 200 条就停，实际只拿到每个市场第一页的 100 只，凑不够 800 只，
  这条备用路径**每次都会判失败**。本功能没碰它，单独记账。
- **上市不满 N+1 个交易日的「N 日涨跌幅」是上市以来涨幅**：粤芯半导 10-13 上市，到 11-06 只有
  19 根日 K，东财给 20 日 = 60 日 = 年初至今 = 128.14%。写库前按交易日历数一下，不够的置空。

### 腾讯行情备用

东财翻页失败时退到腾讯 `qt.gtimg.cn`：市值（亿元）、成交额（万元）、换手、量比跟东财逐个对过一致。
但**名单沿用最近一次东财完整快照**（20 天内），行业也沿用那天的；**不给 5/10/20/60 日涨跌幅**
（存空）。同一天已有东财完整快照时，备用源的结果不覆盖。

## 二、什么叫「完整」

不是「拿到 800 只以上」。全部满足才写库：

1. 每个市场分组翻完全部页（任何一页 4 次都拿不到，整批作废）
2. 每组去重后条数 = 源头报的 total
3. 有效总市值 ≥ 90%（11-06：5229/5563，其余是退市 / 停牌）
4. 总数不比上一次完整批次少 5% 以上
5. 行情带交易日，且**已收盘**（盘中抓到的只记一行批次，status=intraday，不写快照）

不完整的批次**一行都不写**，上一份有效快照原样保留，页面标「数据过期」。每次尝试都记一行
`large_cap_sync_batch`（来源、页数、条数、有效市值数、原因）。

## 三、什么时候跑

| 时机 | 说明 |
|---|---|
| 盘后日更之后 | 15:30 日更 → 板块同步 → 体检 → 板块指数补齐 → **大市值快照**。另起线程 + 子进程，日更不等它、不多占日更的锁；失败不影响日更、不亮「数据降级」 |
| 收盘后手动「更新数据」 | 日更跑完、放掉日更的锁之后接着同步（`--if-missing`，今天已有东财完整快照就秒退），**同步完才报「更新完成」**——顶栏在那一刻刷新全部页面，另起线程的话页面刷新时快照还没写。15:00 前不跑。2026-11-11 之前手动这条没接，15:17 手动更新完页面还停在前一天 |
| 16:40 / 18:40 / 21:40 | 重试（`--if-missing`：今天已有东财完整快照就秒退） |
| 次日 08:45 | 补上一交易日（开盘前行情还停在昨天收盘） |
| 页面「立即同步」 | 要登录。盘中点了也只记批次 |

clist 经常被掐（2026-10 板块同步 15 个交易日里 12 天），所以重试排了四次。有自己的锁
`/tmp/tradeflux_large_cap.lock`，不抢日更那把。

```bash
cd /opt/code/tradeflux/backend
.venv/bin/python -m scripts.large_cap_sync                        # 试跑：抓 + 判完整，不写库
.venv/bin/python -m scripts.large_cap_sync --apply                # 写快照 + 冻结人气核心池（F10 分类默认不补，要补加 --classify）
.venv/bin/python -m scripts.large_cap_sync --classify-only --classify-limit 500   # 只补分类
```

## 四、行业与概念

- **二级行业**：快照里的 f100，一只股票一个，**随快照按天保存**（回看历史就是当天的分类）。
- **概念**：快照里的 f103，同样按天保存。只给总市值 ≥300 亿的存（全存一年要多上百 MB；门槛最低
  预设也是 500 亿），门槛调到 300 亿以下时，下面那截公司没有概念，页面会报数。按名字对 sectors 表
  拿 BK 码和是否关注；表里没有的概念用名字当键，不丢。一只股票可以属于多个概念，同一概念只计一次，
  **各概念的家数和市值不能相加**。默认只看关注概念、且至少 3 家成员。
- **一级行业**：二级按东财行业层级映射（128 个二级 → 31 个一级），映射表
  `backend/app/services/data/em_industry_l2_to_l1.json` 是 2026-11-08 从 F10 采集的（每个二级取一只
  成分股，F10 里排在二级前一位的就是一级）。映射不上的归「一级未映射」并报数。
- **F10 只剩一个用处**：发现层级变化（缓存里有更新的映射时覆盖上面那张表）。2026-11-08 生产上 F10
  每个请求都读超时，所以分类**不依赖 F10**；同步时连续 5 只失败或拉空就停手，不拖时间。
  缓存在 `large_cap_stock_boards`，不碰 StockSectorRelation。

## 五、统计口径

统计母体 = 门槛内的大市值公司（默认 ≥1000 亿、不含 ST），**不是行业全部上市公司**。

| 指标 | 口径 |
|---|---|
| 上涨 / 平 / 下跌 | 当日涨跌幅 >0 / =0 / <0；缺涨跌幅（停牌）的不计入，样本数单列 |
| 中位涨幅 | 有效样本的中位数 |
| 市值加权涨幅 | Σ(前一交易日总市值 × 今日涨幅) / Σ前一交易日总市值。前一交易日没有快照时改用当日市值，页面标「当前市值权重的截面统计」 |
| 主要贡献 | 对加权涨幅贡献最大（按绝对值）的成员和它贡献的百分点。加权为正、中位数为负、贡献大多来自一只 = 一只权重股在拉（11-06 通信：加权 +0.01%，中位 -5.79%，中国移动 +1.67 个点） |
| 背离 | 组的加权涨幅和中位数**方向相反**时标出：少数权重股和多数成员走势不同。展开看「组内权重」（跟加权同一套权重），11-06 通信里中国移动占 51.6% |
| 5D/10D/20D/60D | **当前成员回看近 N 日**的中位数，不是板块指数收益。上市不满 N+1 个交易日的成员这一格写「新股」，不参与中位数 |
| 量比 | 东财 f10 |
| 成交额倍数 | 当日成交额 ÷ 前 20 个交易日均额。前 20 个交易日**每天都要有完整快照、每天都有额且 >0**，否则是空——不拿 5 天均值冒充 |
| 放量 | 成交额倍数 ≥ 2.0，或量比 ≥ 2.0（两个阈值都可配）。上涨放量、下跌放量都列，**不代表净买入** |

**哪天的数**：今天的收盘快照还没同步时，页面显示的是上一交易日的快照。所有原来写「今日」的列名、
指标、榜单标题都改写快照日期（如「11-10」「11-10涨幅居前」），顶部一条蓝框说明。这页只看收盘快照，
盘中不更新。

**页面上的两种提示**：黄框是数据有问题、要人去看（快照过期、前一交易日缺快照、备用源、分类缺失）；
灰字是正常状态说明（第一份快照、20 日成交额历史还在攒）。

**个股链接**：本系统的个股详情只收录进过候选池的股票（11-08 生产：池内 162 只里 47 只没有，
包括建设银行、中国移动），这些点开的是东方财富行情页（新标签页），不进「未找到该股票」。

## 六、跨入 / 跨出

设门槛 T，D-1 是**交易日历上**的前一交易日：

| 结论 | 条件 |
|---|---|
| 跨入 | D-1 有效市值 < T，D ≥ T |
| 跨出 | D-1 ≥ T，D 有效市值 < T（**跨出的票今天不在池里也照样列出**） |
| 首次观测 | D ≥ T，但 D-1 快照里没有它、或没有有效市值（新股、停牌） |
| 今日无有效市值 | D-1 ≥ T，D 没返回或没市值——**不判跨出** |
| ST 变化 | 戴帽 / 摘帽导致的进出，单列，不算市值跨越 |

- D-1 没有完整快照 → 一个事件都不生成，**不拿更早的那天冒充昨日**。交易日历没覆盖到 D 时同理。
- 门槛对两天用同一个值，改配置永远不会被算成「今天有一批公司跨入」。
- 市值变化和当日涨跌幅差 0.5 个百分点以上，标 ⚠：可能是股本变动或口径变化，不解释成资金。

## 七、配置

Pool Config 页「大市值监控设置」，存 `app_config` 的 `large_cap_settings`（只存改过的项）：
门槛（默认 1000 亿）、放量成交额倍数（2.0）、放量量比（2.0）、默认统计窗口（20 日）、是否含 ST（否）。
改配置只是换口径重算，不重新采集。页面顶部还能临时换门槛（不保存）。
