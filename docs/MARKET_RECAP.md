# 每日复盘（Daily Market Recap）

> 2026-11-08 上线 Phase 1。页面 `/market-recap`（侧边栏：主页 → **每日复盘** → 大盘趋势，要登录）。
> 代码：`backend/app/services/market_recap_service.py`（市场事实）、`market_recap_store.py`（人工数据、锁定、验证）、
> `backend/app/routers/market_recap.py`、`backend/app/models/market_recap.py`、`frontend/src/pages/MarketRecap.tsx`。
> 原 `/review`（旧版日复盘）保留。

**定位**：市场事实 → 结构判断 → 核心识别 → 关联研究 → 条件预案 → 次日验证 → 认知改进。
系统给事实，判断和预案是人的；不打分、不预测、不出买卖信号。

## 一、三类数据分开放

| 类 | 存哪 | 能不能改 |
|---|---|---|
| 市场事实 | **不存**。每次按日期从原有各表现算（`GET /market-recap/context`） | — |
| 人工研究 | `market_recaps`（判断、情景、反思）、`recap_watch_stocks`（观察池）、`leader_relations`（关联知识）、`leader_response_daily`（每日响应）、`next_day_plans`（预案草稿） | 草稿随时改 |
| 锁定预案 | `recap_locked_versions` | **只插不改**。改了草稿再锁是新的一版 |

全部按登录用户名（owner）隔离，**接口全部后端鉴权**，不只靠前端 RequireLogin。

## 二、市场事实：按指定交易日取

复盘 D 这天，每个模块只读 D（或 D 及以前的序列），并带 `{status, trade_date, source, note}`：
`ok` 完整、`partial` 部分缺失、`stale` 不是这一天的、`missing` 没有、`error` 这一块查挂了（其余照常，
Postgres 事务会回滚，不连累后面的模块）。

| 模块 | 来源 |
|---|---|
| 指数（上证、深成、创业板、科创50） | `index_daily_snapshots` ≤ D：MA5/10/20/60、均线排列、MA20/60 方向（对比 5 日前）、5/20 日涨幅 |
| 涨跌广度 | `market_breadth_daily` + 涨停 / 炸板明细（封板率 = 涨停 ÷（涨停 + 炸板），明细 0 行 = 没抓到，不是 0） |
| 成交 | 两市成交额、较前日、较近 60 日均额。官方值次日才公布，当天用盘中最后快照并标明 |
| 短线接力 | `market_effect_service.compute_cohort_outcome`（昨日涨停 / 首板 / 连板 / 炸板今日表现，带有效样本数）+ `limit_moves_analysis_service.compute_advance_ladder`（晋级率） |
| 板块 | `sector_mainline_service.get_sector_mainline_state(as_of=D)`；状态基准日 ≠ D 时标 stale |
| 核心候选 | 连板 / N天M板（不连续的那种，跟连板分开）/ 生命周期（直接调 `/leader-cycle` 那个接口函数）/ 成交额前列，各组按上限取（8/5/6/5），**不打分** |

- 未收盘的日子不出复盘；不在交易日历里的日子不出复盘。
- 候选股的板块优先用当天口径（涨停明细的东财行业 → 当天全市场快照的行业），只剩股票表上的
  「当前主板块」时标 `*`。
- 股票日快照的 `pct_change_20d` 是非空列默认 0.0，0 当「不知道」，不显示成 0%。

## 三、观察池与关联

- **观察池跨日保留**，直到主动取消；取消只写 `removed_date`，之前那些天照样查得到。★ = 要建深入关联图谱的。
- **关联知识**（高标 → 属性 → 关联股）跨日继承。依据性质由属性类型决定，不让人手填：
  A 行业及产业链 / 事件催化；B 共享概念 / 历史联动 / 情绪结构；**C 名称联想**。名称联想永远是 C。
  A/B/C 只表示依据性质，不是机会等级。
- **每日响应**单独记，昨天的联动不算今天成立。领先 / 同步 / 滞后**只有两边当天都有首封时间**才允许记
  （首封时间一起存下来当证据）；没有分时证据只能是「未见明显响应 / 无法判断 / 待验证」。
- 关联建议只是建议，采纳了才进表：名称里相同的两个字（客观字符串匹配）、同概念且当天也涨停（板块关联）。

## 四、预案与锁定

- 一天最多 5 只候选；**入场触发和失效条件都必须写**；可以锁「空仓预案」。
- 「进入买入检查」带上代码、止损价、仓位上限跳到 `/pre-trade-check`。预案本身不是买入许可。
- 锁定 = 把当时的判断、观察池、关联（含当天响应）、预案、候选股锁定时的价格事实、各模块数据状态
  整份快照进 `recap_locked_versions`。
- **盘前 / 事后**：锁定时间晚于目标交易日 09:30 的版本标「事后记录」，不能冒充盘前判断。
  目标交易日在锁定时可能还不在交易日历里（日历只到今天），验证时按日历重新确定。

## 五、次日验证

`GET /market-recap/{D}/verification`：用 D 这天**最后一份盘前锁定版本**（没有就用最新一版并标事后），
对照下一交易日的收盘事实：每只候选的次日涨跌、收盘、是否涨停 / 首封、收盘是否跌破计划止损价，
以及当时的姿态和反证条件。入场有没有触发要人对照分时判断，系统不替你补判。草稿不参与验证。
页面上：打开 D 时顶部显示「上一交易日锁定的预案」，⑤ 区显示「这一天预案的次日验证」。

## 六、接口

| 接口 | 用途 |
|---|---|
| `GET /market-recap/dates` | 能复盘的交易日 + 我每天的草稿 / 锁定情况 |
| `GET /market-recap/context?date=` | 当天市场事实 |
| `GET / PUT /market-recap/{date}` | 读 / 存草稿（含预案） |
| `POST /market-recap/watch`、`DELETE /market-recap/watch/{code}?date=` | 观察池 |
| `GET /market-recap/leader-relations/{code}?date=` | 关联知识 + 关联股当天事实与响应 + 建议 |
| `PUT /market-recap/leader-relations`、`DELETE /market-recap/leader-relations/{id}` | 关联增改 / 软删 |
| `PUT /market-recap/responses` | 当天响应 |
| `POST /market-recap/{date}/lock`、`GET /market-recap/{date}/locked` | 锁定 / 历史版本 |
| `GET /market-recap/{date}/verification` | 次日验证 |
| `GET /market-recap/live` | 盘中跟踪（只读，见第九节） |

## 七、V2（2026-11-08）：人气核心池与活跃事件

页面变成三种模式（同一份数据）：**盘后研究**（① 市场状态 → ② 人气核心池 → ③ 主线与观察池 →
④ 高标关联研究 → ⑤ 情景与预案 → ⑥ 复盘结果，顶部是决策摘要 + 三个观察点）、**次日准备**
（锁定版本一屏看完）、**结果验证**。代码：`backend/app/services/popular_core_service.py`。

### 人气核心池（`GET /market-recap/popular-cores?date=`）

多入口召回、按代码并集，**没有人气分**，每只只挂实际满足的依据；排名是竞争排名（并列同名次）。

| 来源 | 规则（core_v1） | 统计范围 |
|---|---|---|
| 5/10/20/60 日涨幅 | 前 20 | **全市场**：大市值同步的全市场收盘快照（东财前复权区间涨幅，新股不足 N 天的已置空）。2026-11-06 起才有，之前的日期这几项是「无数据」，**不拿股票日快照里的「日涨跌幅相加」顶替**（两种算法） |
| 10/20/60 日涨停次数 | 前 10 | **已跟踪股票**（股票日快照只覆盖进过候选池的），不是全 A 股 |
| 当前连板 / 60 日高板 | 前 10（≥2 板 / ≥3 板） | 已跟踪股票 |
| 成交额 | 当日前 20；近 5 个交易日 ≥3 次进前 20 | 成交额前列名单 |
| 生命周期重启 | 断板/失败→修复、修复/走弱→二波确认 | 生命周期快照 |
| 我的重点 | 观察池 | 不受榜单淘汰 |

「辨识度依据」和「当前状态」（生命周期）分开显示。观察视角：今日活跃 / 历史人气 / 修复观察 /
我的重点 / 全部候选，不互斥、不是收益等级。可按板块（主板 / 创业板 / 科创板，涨跌停制度不同）筛。

**冻结**：大市值快照同步成功后自动冻结当天的池子和事件（`market_popular_core_runs / _daily`、
`leader_activation_events`，同一天同规则版本是覆盖）。之后读那天只读冻结的；没冻结的日期现算，
用的也全是那天的数据，只有「涨停次日均」是股票表上的当前值，所以**现算历史日期时不回填**它。
手动：`python -m scripts.popular_core build --date D [--apply]`；覆盖审计：`python -m scripts.popular_core audit`。

「涨停次日均」一律带样本数：是次日**收盘**涨跌幅的平均，不是次日开盘能买到的收益，样本只来自已跟踪股票。

### 活跃事件（`GET /market-recap/leader-activations?date=`）

今日涨停、再次涨停（昨天没涨停且之前 60 日最高 ≥2 板）、连板延续、断板、修复启动 / 确认 / 失败
（生命周期转移）、放量异动（量比 ≥2）。只用当天已收盘数据；**数据缺了不出事件**：今天没快照不判断板，
昨天没快照不判再次涨停 / 连板延续。关键价格突破要先有你写的价格条件，还没接。事件只是提醒去看关联池。

### 关联研究

两层，分开显示：

1. **板块关联（自动，`GET /market-recap/leader-sectors/{code}?date=`）**：高标所在的每个板块（跟活跃股池
   里的板块标签同一份——Sector Config 关注的行业 / 概念，主板块在前），各列出**当天**的活跃股：那天的
   强势池、那天涨停、那天跌停。一只票在高标的几个板块里就在每个下面都出现（标「+N板块」）。
   板块归属是当前口径（板块关联表不存历史）；没有板块归属的活跃股会报数。这是当天事实，不进知识库，
   点「记为关联」才进。
2. **其他关联（人工录入的长期知识）**：产业链、事件、名称、历史联动……加上名称联想建议。
   「同概念且当天涨停」的建议已经被第 1 层覆盖，不再单独建议。

- 系统响应分类（事实，按写死的条件）：已涨停 / 满足上涨响应条件（当日 ≥5%）/ 高标转弱（≤-3% 或断板）
  时独立走强 / 尚未满足 / 数据不足。「尚未满足」≠「没响应」。人工记录（领先 / 同步 / 滞后…）另列。
- 摘要按股票去重。批量采纳 / 批量忽略（忽略 = 记成「不成立」，不再建议，勾选可见）。
- 名称建议带「重名数」（含这两个字的股票有几只，越少越具体）；常见字带来的噪声摆出来让人筛。
- 每条关联可以「观察」（进观察池）或「拟交易」（进预案草稿，预填关联依据；入场 / 失效还得自己写）。

### 情景与预案

情景按 ★ 重点高标分别写（`scenarios.by_leader`），也保留全局一套；V2 只加字段不改旧字段名。
预案多两个字段：**关联依据**、**观察触发**（高标出现什么才去看它——不是买点），跟它**自己的入场触发**分开。
锁定快照里多存当时的人气核心池（成员 + 选入理由）和活跃事件；之后新冒出来的票不会补进旧版本。

## 九、盘中跟踪（2026-11-09）

页面第四种模式「盘中跟踪」（盘后研究 → 次日准备 → **盘中跟踪** → 结果验证）。工作日 09:15–15:00
打开页面默认进这里，网址 `?mode=live`。接口 `GET /market-recap/live`（要登录）。
代码：`backend/app/services/market_recap_live_service.py`、`frontend/src/components/marketRecap/LivePanel.tsx`。

**跟盘后复盘严格分开**：

- **只读，一行不写**：不落库、不冻结核心池、不碰锁定版本、不进活跃事件表、不记人工响应。
- 盘中事件**全部是临时的**（页面虚线框 +「盘中临时」）。叫法也跟收盘事件分开：封板中 / 再次封板 /
  连板中 / 暂未连板 / 炸板 / 跌停——盘中说「今日涨停」「断板」都太早。
- 拿不到 = 未知：没行情的票写「没行情」，行情日期不是今天写「非今日」，今天没成交写「未成交」；
  统计只用拿到的、带样本数。涨停池或炸板池任一没拿到就不算封板率。
- 涨停 / 炸板 / 跌停走 `kline_bar_from_quote`（跟日更补 K 线同一套），不另写一份。

**时段**以行情自带的市场时间（腾讯字段 30）为准，收没收盘走 `bar_is_settled`；本机时钟只用来分盘中的几段：

| 时段 | 条件 | 自动刷新 |
|---|---|---|
| 集合竞价 / 竞价结束 / 盘中 / 尾盘集合竞价 | 行情是今天的，按本机时钟分段 | 30 秒 |
| 午间休市 | 11:30–13:00 | 到 13:00，最长 5 分钟 |
| 已收盘（盘后同步前） | 行情时间 ≥ 15:00 | 不刷 |
| 未开盘 | 行情还停在上一交易日、09:15 之前 | 等到 09:15，最长 10 分钟；周末不刷 |
| 休市 / 行情没更新 / 行情时间未知 | 日历说今天不开市 / 过了 09:15 行情还是旧的 / 指数行情没拿到 | 不刷 / 1 分钟 / 1 分钟 |

页面在后台时不刷；可以关掉自动刷新，手动刷。

**执行哪天的预案**：行情是今天的 → 上一交易日 R 锁定的预案（最后一份盘前版本，没有就最新一版标「事后」；
一份都没锁就用 R 的草稿，标「草稿」）。行情还停在 R（开盘前、休市）→ R 锁定的、给下一交易日的预案，
价格是 R 的收盘。交易日历落后时（盘中今天不在日历里是常态，落后指中间还夹着工作日）页面红字提示
「执行哪天的预案」不一定对。

**内容**：

| 区 | 内容 | 来源 |
|---|---|---|
| ① 市场此刻 | 四个指数；涨跌家数；封板 / 炸板 / 封板率 / 最高板；两市成交额（此刻累计、预估全天 vs 昨日）；R 的涨停 / 连板 / 炸板那批票此刻的中位涨幅、红盘率、封板数 | 腾讯行情（指数单独一次请求，跟平安银行 000001 不串号）；东财涨跌分布；东财涨停池 + 炸板池；新浪 5 分钟 / 东财分钟成交额（风向标同一个函数，这里不落库）；`_cohort_snapshots`（跟市场效应同一个群体定义） |
| ② 今天执行的预案 | 姿态、三个观察点、失效条件；每只候选的现价、涨跌、封板状态、距计划止损（已破标红）、入场触发 / 失效条件原文、买入检查入口 | 锁定版本 payload + 实时行情。入场有没有触发要人对照分时判断，系统不替你判 |
| ③ 重点高标与关联股 | ★ 高标此刻状态 + 临时事件；关联股（一只票多个属性合并一行）此刻涨跌、首封时间、系统响应分类（临时） | 当前关联知识库（不是锁定时的快照）；`classify_response` 同一套条件，高标「暂未连板」等同断板 |
| ④ 我的观察池 | 观察池全部股票此刻涨跌、状态 | 当前观察池 |
| ⑤ 人气核心池 · 此刻 | R 的核心池（冻结的读冻结的）× 此刻行情，默认只看「盘中有事件」 | `popular_core_service.load` |
| ⑥ 此刻涨停池 | 按连板高度、首封时间排；标出核心池 / 观察池成员 | 东财实时涨停池 |

首封时间只来自东财实时涨停 / 炸板池，池子没拿到就没有首封时间（不拿行情时间顶替）。领先 / 同步 / 滞后
还是要去盘后研究里人工记，盘中跟踪不写。

**缓存**（进程内）：个股行情 15 秒、全市场几路 30 秒、R 的核心池 10 分钟；外部数据最多等 8 秒，
没回来的这次标未知，线程跑完照样进缓存，下次刷新就有。本机实测有缓存时 30~40 毫秒，冷启动约 4 秒。
